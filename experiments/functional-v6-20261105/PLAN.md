# 第六轮准备：扩充原始请求与真实照片覆盖

状态：来源与请求范围核验中，未开始本轮标签训练或模型推理；不是已证实的改进。第五轮已停止，最终验收仍封存。所有新GPU工作继续使用原16占用GPU小时预算，GPU1原演示服务保留。

## 为什么改数据

第四轮仍只在60张照片上训练，其中10条自然请求反复采样；第五轮连续参数头虽然最多完成4/6原始请求，仍有严重反向编辑。继续改变结构不能替代真实请求覆盖。本轮从完整、已存在的25763条原训练资源中查找原始标注，超出旧3000条抽样的范围，但不把旧参数或参考图自动当成新标签。

请求先与原GIER的request、expert_summary或amateur_summary逐条核对，允许空白规范化核对，保存原存储英文及标注位置，不由AI改写英文来迎合标签。中文翻译、所有合成请求另外标明。来源检索不是入训批准，空指令、局部编辑、非照片、未开放效果以及无法可靠验收的记录不能直接使用。

## 计划数据与先后顺序

1. 先核验原始请求的开发与验收照片，逐条写明应改变、应保留、失败现象，中英文同组。计划新增原始请求开发20张／20语义案例、人像与风景各10；原有100任务开发集与6条已使用的请求继续作回归，不把重叠原图当独立样本。
2. 另从原test_reserved照片准备原始请求验收20张、人像／风景各10，只观察来源及冻结要求；不运行任何候选模型。原有20张／100任务验收继续封存，两个验收部分都只能在最终权重和运行时锁定后运行。
3. 训练目标争取100张新原图的100条原始请求、人像／风景各50，加原有60张受控课程照片的360条已核验任务。这样为160个训练原图组、460语义案例、920条不重复中英文记录；原始请求占100/460，不再用10条重复100次假装更广覆盖。候选源最初按80张原始请求准备；在任何入训前将目标提高到100张，以使真实原图数达到160。数量不足则继续寻找与核验，不以未审数据补齐。
4. 每条新标签实际执行并直接看图。可比较原模型输出、原标签重新映射以及独立参数提案，最终依据可见的请求完成和质量选择。请求改写与反向合成不能沿用原参考图。原有60对同图不同状态／力度要求和保持不变任务继续保留。
5. 近重复检查覆盖历史父模型训练、历次留出、新训练与开发／验收。已发现一个直接看图相似而旧pHash规则漏掉的案例对（development-native-056/151，pHash距离16），因此增加ORB几何匹配和人工关联记录。所有涉及最终所选集合的冲突必须解决；不把自动无碰撞误当成能检测所有裁剪或相邻拍摄。

开发候选使用历史validation_reserved原图。部分照片在以前的开发或来源分类中看过，扩展候选时如实保留历史；它不是新采集的独立用户测试。模型输出尚未生成，最终案例冻结后不能凭模型表现替换照片或改要求。

## 待数据入训后比较的路线

计划比较“原始Qwen重新训练”与“第二轮课程e3继续训练”，使用完全相同的新数据、提示、编辑器、随机种子与更新次数，检验是否需要摆脱旧错误标签的积累。仍用NF4 QLoRA、语言q/v、rank8、alpha16、有效batch4；具体学习率、轮次、所有代码及哈希在真实数据通过后另行冻结。输入恢复为已核验的图像＋原始请求＋工具说明，不自动翻译或外部改写。不在本轮继续使用第五轮失败的小头。

首要门槛是原始请求的真实完成与零重大副作用。计划把新20条原始开发要求的双语合格目标提前定为至少16/20，同时受控开发不低于81/100、原6条回归超过3/6，各组无严重副作用；这些数值必须在任何本轮模型输出前写入正式协议。它们是研究门槛，不是用户认可。最终验收后的新模型不得再因测试结果换检查点；达不到就报告失败，不以L1或训练损失宣布实用。
