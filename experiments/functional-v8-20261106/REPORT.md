# 第八轮：修图结果评审器校准（2026-11-06）

本配置未通过校准，未用于训练奖励，也没有启动新的编辑策略训练。它识别不了部分反向调整和画质问题，不能用更高的自动评分替代真实修图验收。

方法来源为[EditScore官方项目](https://github.com/VectorSpaceLab/EditScore)与[论文](https://arxiv.org/abs/2509.23909)。使用作者公开的EditScore-7B LoRA，revision `dcce052accfc75f2d48279c889a71755ecdf737b`，323,020,048字节，SHA `b78dc22fea2ebedfa17780a71ece05cec7062e6b738eeb3e2d21740cd44d7297`；它与现有Qwen底座revision完全相同。仅加载冻结权重，没有声称本项目训练了该评审器。源码commit `4609c5d2ebb62fdebf665d3c924686d896ef1f74`与Apache-2.0许可保留。

18个原图组全部来自此前使用的训练池，人像／风景各9组，未读取开发或验收图。10个方向任务各有中英文，比较已经直接核验的目标、不操作原图和新构造的反向结果；新反向图均经Codex直接看图。另8组画质比较为此前原尺寸AI评为合格与轻微副作用的照片，各4人像／4风景；部分比较是同一照片不同修图要求的结果，只测试不接收指令的PQ画质分支，不冒称原失败任务修好了。它不包含重大损伤识别认证，也没有人工认证。外部预训练数据与GIER是否重叠未知，不能称为独立测试。

两条冻结路线：原始Qwen、原始Qwen加官方EditScore适配器。均采用同一官方提示与img1/img2模板、完整BF16、单次采样、种子20261114、temperature0.7、top_p0.9、top_k20、最大512新token。每张图限262144像素，使用sdpa。JSON非法、歧义、重复键、越界、NaN、截断一律失败，没有采用官方包的补分、猜分、修复或自动重试。76条模型输入CPU审计通过，8种非法评分响应拒绝检查通过。

预定要求：至少9/10个任务中，正确目标在中英文都严格胜过不操作和反向结果；8/8画质对照正确。平分和无效响应计失败。方向只用第一个“指令完成”分量；一致性不能弥补反向编辑。PQ用自然度和瑕疵两个分量中的较低值。分量定义补充保存时已有基础17条、EditScore16条输出落盘，但尚未查看任何评分；补充前后阈值、样本、提示、生成设置均未变，收据如实保留。GPU前协议、原始CPU协议和重复键解析补充均可追溯，没有覆盖旧文件。

例子：train034要求调暖，实际正确图明显暖、反向图明显偏蓝，但EditScore在中文给三个版本同为23，英文同为0；train220要求恢复褪色，中文正确图0而反向继续去色图20；train201要求棕褐色，英文棕褐正确图18、偏蓝反向图19。n119画质对照中，修复后合格图13、已有轻微损伤图18；n186与x030画质对照平分。对应图片在`calibration-candidates/`及清单引用的第七轮原尺寸图，全部原始响应在`reward-calibration/*/predictions.jsonl`。

这不是在否定论文的通用结果，只说明本项目当前分辨率、采样与真实照片调色场景下，这个具体配置不足以提供可靠奖励。禁止据此自动选择标签、训练RL或宣布模型可用。结果不影响第七轮冻结记录、默认服务或封存验收。
